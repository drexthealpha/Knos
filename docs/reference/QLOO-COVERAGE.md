## Where docs.qloo.com and the task differ (the docs, or the live API, win)

- filter.type for games is urn:entity:videogame: urn:entity:video_game is answered 400 'not supported for filter.type'.
- signal.demographics.age takes 24_and_younger, 25_to_29, 30_to_34, 35_to_44, 45_to_54, 55_and_older (Parameter Reference); the task's '35_and_younger' is not one of them, so F1's check compares 24_and_younger with 55_and_older.
- Hotel price range: the Entity Type Parameter Guide says filter.price_range.from/to, the Parameter Reference says .min/.max; the API acts on from/to (min/max returned the unfiltered list).
- Resy: the Guide says filter.properties.resy.rating.*, filter.resy.rating_count.*, filter.resy.rating.party.*; the Parameter Reference says filter.external.resy.rating.*, .count.*, .party_size.*; the API acts on the filter.external.resy.* names.
- heatmap.dimensions with filter.dimensions.price_level/hotel_class applies only with filter.type=urn:heatmap and output.heatmap.boundary=urn:geohash (Parameter Reference).
